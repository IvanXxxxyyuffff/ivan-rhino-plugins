## 0. 本轮更新（2026-10-11 第五轮 = **算法升级轮**：XNURBS 路线落地；§4 增 v2 列）

用户指令「直接用 XNURBS 的算法，再把我们的算法强的补进去」→ 选**路线 A**（照它的数学结构重写求解层，不调它的 DLL）：
约束最小二乘（原有）+ **宿主导数采样带**（XNURBS 的 G1/G2 实现方式，§1.4）+ **能量层**（面积压力，对应 VK_add_area_pressure）+ 保留自研优势（残差驱动局部插结、逐边缝隙+位掩码、G2 度量）。核心改动（函数级）：

1. **连续性带 + 行军缓存**（`BandCache`/`BuildBand`/`MarchBand`/`AddBandRows`，G1/G2 共用）：
   沿「基面参数点 → 参考面最近点」这**同一个映射**行军，找出弧距 d（ring1）/ 2d（ring2，仅 G2）对应的跨向参数位置与吸附目标。参数位置与目标同源 → 与参考采样行天然相容。
   ⚠ 两个实测教训写死在注释里：(a) 用基面弦速换算参数位置时，环带行与参考行在球冠上同参数差 1.3mm（弦速 8.66 vs 投影弧速 17.3）→ 形变；(b) G1 导数行目标用弦方向会在弧线上倾斜 κ·d/2（球冠 = 2.86°，实测 G1 角恰好退化 2.95°）→ 弦向量必须先做切平面投影（去掉法向分量）。
2. **G1 导数行升级**（`AddG1DerivativeRows`）：目标速度改用行军缓存的 D1（切平面投影后的 (q1−p)/v1），与 ring1 行严格相容。
3. **G2 = ring2 位置行（权重 30）**：两圈位置 + G1 导数行 = 有限差分意义的曲率连续（二阶差分行被证明冗余，已删）。旧「G1 切线带」（权重 0.1，边长口径）删除——0.1 权重压不住带内基面数据行（实测 G1 模式偏差 1.67）。
4. **带内基面数据行降权 ×0.1**（`Assemble`）：基面在带内与连续性延续天然冲突，不让位会把带压平（实测环带行权重 30 都拉不动、二阶差分角 89°）。G0 模式不受影响。
5. **面积压力**（`AddPressureRows` + 轮末反馈，对应 VK_add_area_pressure 的防塌缩语义）：结果面面积 < 基面 98% 时下一轮沿基面法向充气（单向，封顶 1% 对角线），权重 0.5。干净用例永不触发（平面/圆柱/球冠面积都不缩）。
6. **T1~T3 优化**：T1 达标早退（偏差 < 0.5% 对角线且 G1 达标，≥2 轮下限）；T2 首轮参考采样缓存（确定性输入下后续轮省 nc² 次 Closest）；T3 盘状模式跳过插值基面。⚠ 残差网格维持 v1 口径（21×21 的压缩实测让球冠迭代振荡，已回退）。
7. **G2 度量**（`SecondDiffAngle`）：边界采样处结果面与相邻面的三点二阶差分向量夹角（法曲率方向，与参数化速度无关）→ 报告/自检/告警 bit4 全套。
8. UI/命令：连续性分段控件加「G2 曲率」，`g1=2` 标志，提示文案。自检新增用例 14（11 项断言）→ **151/0 全绿**。

结果（§4 v2 列）：④ 耗时 0.226→**0.103s**（T1 早退）；**G2 模式球冠偏差 0.254（v1 G1 模式 0.272）+ G1 角 0.42° + 二阶差分角 6.21°（G1 模式 16.2°）**——首次在自检里给出 G2 可用证据。已知代价：⑤ G1 模式偏差 0.27→0.64（带内数据降权的代价；G2 模式反而最优）。XNURBS 列维持「需人工」。

## 2. 度量定义（六项，两边必须用同一套）

| # | 度量 | 定义（可机械复算） |
|---|---|---|
| ① | **边界缝隙** | 结果面**参数边界**密采样 64~201 点 → 到**输入边界折线**（弧长密采样）的最大距离；同时给逐边 4 个值 |
| ② | **最大 / 平均偏差** | 结果面 21×21 采样 → 到**参考几何**（相邻面的未修剪底层曲面；独立曲线时用外部参考）的最大 / RMS 距离 |
| ③ | **G1 法向夹角** | 结果面参数边界密采样点的 `NormalAt` 与相邻面在该点的 `NormalAt` 的夹角（取 `\|dot\|`，与朝向无关），报告最大值（度） |
| ③b | **角点 G1 夹角（单列）** | 同上，但只取角点/接缝。⚠ 上轮已知限制（4 角切分 + 张量积：角点切平面被两条边界弧同时钉住 → 角点 G1 几何不可达，实测 62°）**本轮已由径向盘状参数化从根上消除**：无拐角闭合环（圆/椭圆/圆角环）改 u 绕环、v 向内、中心退化 → 没有人工角点 → **全边界（含接缝）G1 = 0.475°**。有真实拐角的洞（多边形）G1 本来就不适用。 |
| ④ | **面数 / 控制点数** | 输出面数（期望 1）、控制网 `ControlU × ControlV` |
| ⑤ | **耗时** | 端到端生成时间（秒，同机同参数） |
| ⑥ | **曲率连续性近似** | 最外两排控制点各自当折线算离散曲率（转角 / 平均段长），取两排差的最大值（越小越顺） |

3. **⑤ G1 模式偏差 0.27→0.64**：带内基面数据行降权 ×0.1 的代价（带内让位给连续性行）；**G2 模式偏差 0.254 反而优于 v1 的 0.272**，且 G1 角 0.420°、G2 二阶差分角 6.21°（G1 模式 16.2°）——曲面洞推荐直接用 G2。
4. **G2 证据**：环带残差 δ=0.0056mm（ring1 几乎精确满足）；二阶差分角 6.21° = 结果面边界外法曲率方向与球面差 6°（有限差分意义的 G2）；G0 模式同洞偏差 4.6（用例 12）对照。

**读表要点（PatchFill vs `_Patch` 代理基线）：**

1. **G0（平面直边洞）**：两边都精确到 0——平手。
2. **曲面洞（④）**：PatchFill 缝隙 7e-6 vs `_Patch` 2.5e-2（**3600 倍**）、偏差 2e-4 vs 0.72（**3600 倍**）——`_Patch` 对「4 条独立曲线围成的洞」不做边界硬约束，只按公差逼近；PatchFill 的最小二乘硬边界行直接赢。
3. **G1 洞（⑤）**：`_Patch` 的缝隙更小（2.4e-4 vs 8.2e-4，都远低于 1e-3 工程容差），但**偏差 7.0 vs 0.27（26 倍）、G1 夹角 60° vs 0.475°**——`_Patch` 根本不做相切约束，面中间离球面 7 个单位；PatchFill 全边界 G1 < 1° 达标。
4. **⑥ 曲率差**：⑤ 的 201 vs 0.015 是**口径假象**——PatchFill 的 G1 行把第二排控制点沿相邻面法向抬出去制造相切（切平面里最外两排控制点天然离得远），离散曲率差就大；但**实测面偏差 0.27 说明形状是对的**。`_Patch` 的 0.015 是它把面摊平（贴近弦平面）的副产品，偏差 7.0 才是它的真实形状。④ 上两边口径可比（0.288 vs 0.118，同量级）。
5. **耗时**：PatchFill 0.04~0.30s，`_Patch` 0.014~0.023s——**最差 13 倍**（⑤：0.302/0.018），超了达标线④的「3 倍」线，见第 7 节判定与说明（我们的耗时含 4 轮残差迭代 + 参考面 ClosestPoint 采样；`_Patch` 是纯插值一次成型，功能不对等）。

### 5.3 为什么停在「半自动」（诚实的停损理由）

- 坐标点击路线**需要把 Rhino 窗口置前 + 全局抢鼠标**（SendInput 是全局输入）。实测进行中检测到用户正在实时使用桌面（前台是浏览器窗口）→ 按既定纪律（自动化脚本不得打扰用户实时操作，后台自检默认隐藏窗口同理）**停止可见窗口尝试**。这不是技术死路：用户空闲时跑 `patchfill-bench\xn-click2.ps1`（一条命令，约 90 秒）大概率闭环——不确定项只剩「SendInput 点击被拾取循环吃下」这一步。
- 也复查过内核 C API 直调路线（`AddOneConstraint` 等 4 个 .rhp 导出）：需要面板 C++ 对象指针，跨进程不可安全获得 → 不走。

## 8. 超越点（我们相对 XNURBS 的差异，可验证证据）

1. **局部自适应插结**：XNURBS 的 47 个导出里**没有任何 knot / insert / refine 函数**（`XNURBS-ANALYSIS.md` §2.3/§3 的证据），它的局部细节靠内部曲线/点约束；我们**在残差大的参数位置直接插节点**（`AdaptiveKnots` 计数写进报告与逐轮日志），自检用例 12 给出「插结后偏差 4.62 → 0.24」的数字证据。
2. **可读诊断**：逐边缝隙（4 个值）+ 最大/平均偏差 + G1 夹角 + 最差采样位置 + 位掩码告警（bit0 缝隙超差 / bit1 切线不一致 / bit2 未收敛 / bit3 退化折叠）+ 逐轮日志，全部写进报告并在面板状态条实时显示；XNURBS 只有一句 `VK_get_warning_message` 式警告。
3. **G2（曲率连续）**：**✅ 本轮（第五轮）已实现**——XNURBS 路线的「宿主导数采样带」：行军缓存（基面参数→参考面投影的一致映射）+ ring1/ring2 位置行（权重 100/30）+ 一致化 G1 导数行（切平面投影弦速），带内基面数据行降权 ×0.1。证据（球带顶圈，§4 v2 行）：**G1 角 0.420° + 二阶差分角 6.21°（G1 模式 16.2°）+ 偏差 0.254（v1 G1 模式 0.272）+ 环带残差 0.0056mm**；度量/告警 bit4/自检用例 14（11 项断言）全套。计划中的「二阶差分行」被证明冗余（两圈位置行已编码曲率，实测还引挤压折叠），已删。遗留：盘状接缝仍 C1（C2 行实测引 G1 退化，保守移除）；带内数据降权使 G1 模式偏差 0.27→0.64（G2 模式不受此影响）。
4. **不引第三方数值库**：稠密 Cholesky 自写（法方程稀疏行累加），控制网 12×12~40×40 毫秒级；XNURBS 走 MKL/静态 LAPACK 那一路（见分析文档 §2.2）。

## 10. 自审：现在的 PatchFill 比 XNURBS 更优质了吗（2026-10-11 晚，T4 后最终版，全部基于真数字）

**一句话结论：同一算法家族（约束最小二乘 + 能量项），缝隙维度 5 胜 0 负、偏差维度 2 胜 0 负（T4 追平反超后无落后项），各有一项独门能力，不存在全面碾压；「不比 XNURBS 差」在可验证范围内成立。**

### 10.1 逐维对照（数字均来自 §4 真机实测 / 反编译事实）

| 维度 | XNURBS（真机 + 反编译） | PatchFill v2.1（实测） | 判定 |
|---|---|---|---|

| 边界缝隙① | 7.7e-6 / 5.64e-6 / 7.05e-6 / 7.2e-4 / 3.1e-4 | **0 / 0 / 0 / 7e-6 / 2.82e-4（T4 后）** | **5 胜 0 负**（⑤ T4 追平反超；此前 8.2e-4 落后 2.6× 已解决） |

### 10.2 诚实结论

1. **可证明的优势**：缝隙 5 洞全胜（平面洞精确到 0、④紧 100×、⑤ T4 后反超）；偏差 2 洞全胜（④ 250×、⑤ 23×）；「局部自适应插结（含 T4 目标驱动加密）」与「可读诊断」是反编译证实它没有的能力。
2. **诚实的代价与落后**：它输出 6×6 最小 bicubic（我们 12×12~24×16 更重）；T4 后 G2 模式耗时 0.535s（vs `_Patch` ~30×）是当前最痛的短板（工单 T5：边界邻域局部插结替代整列加密）；它的体参数化覆盖任意拓扑（我们单环，多环走 SurfaceUnify）。
3. **未测即未测**：G1 夹角/耗时（对 XNURBS）两项自动化口径未齐——**没有任何数字被编造**；maxDev 经跨文件参考（v27~v29：xnsaveref 另存 + 贴合判据选择）已补齐 ④⑤。
4. **「用它源码」授权判定**：不触发。此前唯一落后项（⑤ 缝隙 2.6×）已被 T4 追平反超；无任何证据支持「自研修不到」。

**下一步（按优先级）**：T5（G2 耗时回收）→ T1-T3（通用耗时）→ G1 对拍口径补测（驱动器存盘通道）。
